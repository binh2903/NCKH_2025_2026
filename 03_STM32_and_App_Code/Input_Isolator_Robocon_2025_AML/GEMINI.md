# Input Isolator Robocon 2025 (AML Team)

## Project Overview
This project is an **Input Isolator and Real-time Monitoring System** designed for the AML Robocon 2025 team. It uses an **STM32F103** microcontroller to read 16 isolated digital input pins and transmit their logic states via UART to a PC. A Python-based visualization tool provides a real-time bar chart of all input states.

### Key Technologies
- **Microcontroller:** STM32F103 (ARM Cortex-M3)
- **Framework:** STM32 HAL (Hardware Abstraction Layer)
- **RTOS:** FreeRTOS (CMSIS-RTOS v1 API)
- **Build Systems:** CMake (preferred) and Keil MDK-ARM
- **Monitoring:** Python 3 with `pyserial` and `matplotlib`

### Architecture
- **Firmware (C/FreeRTOS):**
  - `inputReadTask`: Reads 16 GPIO pins (PA0-PA7, PB0-PB2, PB10-PB14) every 10ms and stores the state in a 16-bit bitmap.
  - `inputSendTask`: Transmits the bitmap over UART1 every 50ms using the format `IN:0xXXXX\r\n`.
  - **I2C1 & UART1:** Configured for external communication.
- **PC Tools (Python):**
  - `io_monitor.py`: Connects to the STM32 via Serial (default COM3, 115200) and displays a real-time bar chart.

## Building and Running

### Firmware (STM32)
#### Using CMake (Recommended)
1. Ensure you have `arm-none-eabi-gcc` and `cmake` installed.
2. Configure the project:
   ```bash
   cmake -B build -G Ninja --toolchain cmake/gcc-arm-none-eabi.cmake
   ```
3. Build:
   ```bash
   cmake --build build
   ```
4. Flash the `.elf` or `.bin` file using OpenOCD or STM32CubeProgrammer.

#### Using Keil MDK-ARM
1. Open the project file: `MDK-ARM/Input_Isolator_Robocon_2025_AML.uvprojx`.
2. Compile and flash using the Keil IDE.

### Monitoring Tool (PC)
1. Install Python dependencies:
   ```bash
   pip install pyserial matplotlib
   ```
2. Run the monitor (adjust port as needed):
   ```bash
   python io_monitor.py --port COM3 --baudrate 115200
   ```

## Development Conventions

### Coding Style
- **HAL Standards:** Adhere to the code structure generated by STM32CubeMX. Place user code strictly within `/* USER CODE BEGIN */` and `/* USER CODE END */` blocks to prevent loss during re-generation.
- **Naming:** Follow the existing project prefixing (e.g., `IN_1_Pin`, `MX_GPIO_Init`).
- **UART Communication:** Use the `uart_printf` helper function for formatted output; it uses a mutex (`uartMutexHandle`) to ensure thread safety.

### Peripheral Mapping
- **Input Pins:** 16 pins mapped from `IN_1` (PA0) through `IN_16` (PB14).
- **Status LED:** `STT_LED` on PA10.
- **UART:** UART1 (TX on PA9, RX on PA10 - *Note: PA10 is also shared with STT_LED in config, verify schematic*).

### Testing
- Verify input isolation by toggling physical inputs and checking the `io_monitor.py` output.
- The firmware includes a queue (`ioDataQueueHandle`) to ensure no input state changes are missed between reading and sending tasks.
